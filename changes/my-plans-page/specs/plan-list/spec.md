# 能力规格：我的计划页（列表 / 搜索 / 入口 / 导航）

## Purpose

「我的计划页」是用户查看与管理旅程计划列表的入口页：以卡片列表展示已创建计划（仅区分草稿/非草稿两种卡片），支持按名称关键字搜索，并提供新建旅程入口与底部导航，对应需求 FR-PL-01、FR-PL-03~05、FR-PL-07 与 FR-NAV-01。页面结构与视觉以 `docs/journey-plan-prototype.html` v5 为基准。产品决策（2026-08-28）：状态系统全面取消，FR-PL-02 状态筛选与 PRD 3.2.2 四态派生不在本能力内。

## ADDED Requirements

### Requirement: 计划卡片列表展示（FR-PL-01）

The system SHALL 以卡片列表形式展示已创建的计划，每张卡片包含计划名称、时间范围、天数、人数、总预算、进度（已生成每日计划数/总天数）；卡片仅区分「草稿/非草稿」两种样式，无四态状态标签。

#### Scenario: 非草稿卡片展示

- **WHEN** 列表包含非草稿计划（已进入后续流程）
- **THEN** 卡片按原型结构展示：统一柠檬渐变封面与日期角标，信息区含名称、时间范围·天数·人数·总预算、进度条与「每日计划已生成 X / Y」文案；不显示任何状态标签

#### Scenario: 草稿卡片展示

- **WHEN** 列表包含尚未进入后续流程的草稿计划
- **THEN** 卡片为虚线边框样式，展示编辑图标头、名称、「草稿」标签与「已完成命名与基本信息，可继续生成每日计划」引导文案；日期/人数等已填写要素正常显示，未填写要素以占位样式展示（如「待完善」）

#### Scenario: 计数文案

- **WHEN** 用户查看列表
- **THEN** 页面头部展示「共 N 段旅程 · M 段可见」（N 为计划总数，M 为当前搜索下的可见数）

#### Scenario: 空列表引导

- **WHEN** 用户进入「我的计划」页且不存在任何计划
- **THEN** 页面展示空态提示与「＋ 新建一段旅程」引导入口

### Requirement: 关键字搜索（FR-PL-03）

The system SHALL 支持按计划名称关键字搜索：忽略大小写、支持模糊（子串）匹配，输入防抖 ≥300ms；无结果时展示空态与新建引导。

#### Scenario: 模糊且忽略大小写匹配

- **WHEN** 用户输入与计划名称子串匹配的关键字（不区分大小写）
- **THEN** 返回名称包含该子串的所有计划

#### Scenario: 输入防抖

- **WHEN** 用户连续快速输入多个字符
- **THEN** 系统在输入停顿 ≥300ms 后才发起查询，避免每次按键都请求

#### Scenario: 无结果空态

- **WHEN** 搜索关键字无任何计划匹配
- **THEN** 展示无结果空态（文案参照原型「没有找到匹配的计划 · 试试其他关键字，或新建一段旅程」）与「＋ 新建一段旅程」入口

### Requirement: 新建旅程入口（FR-PL-04）

The system SHALL 在列表页提供「新建一段旅程」入口：列表底部常驻虚线按钮，空态同样提供该入口；点击进入制定计划 Step1（命名页）。

#### Scenario: 底部常驻入口

- **WHEN** 列表滚动到底部（无论列表是否为空）
- **THEN** 可见「新建一段旅程」虚线按钮

#### Scenario: 进入 Step1

- **WHEN** 用户点击新建入口
- **THEN** 跳转到 Step1 命名页（STEP 1/3 步进器样式，参照原型）

### Requirement: Step1 计划命名（FR-WZ-01 子集）

The system SHALL 在 Step1 提供计划名称输入：必填、2-20 字符、去除首尾空格；页面样式参照原型（STEP 1/3 步进器、名称输入框、「下一步」主按钮）；提交即保存草稿并返回列表。

#### Scenario: 校验提示

- **WHEN** 用户提交时名称去除首尾空格后长度不在 2-20 字符
- **THEN** 给出校验提示且不创建（提示文案参照原型「请为计划起一个名字（2-20 字符）」）

#### Scenario: 提交保存草稿并返回列表

- **WHEN** 用户输入合法名称并提交
- **THEN** 系统保存草稿计划并返回「我的计划」列表，新计划出现在列表顶部（更新时间倒序）且带「草稿」标签

### Requirement: 卡片编辑与删除（FR-PL-05 / FR-PL-07 子集）

The system SHALL 在每张计划卡片提供「编辑」与「删除」操作：「编辑」可修改计划名称（校验同命名），「删除」需二次确认后物理删除。

#### Scenario: 编辑名称即时生效

- **WHEN** 用户点击卡片「编辑」并提交合法新名称（2-20 字符，去空格）
- **THEN** 名称修改成功且列表即时刷新；非法名称给出校验提示且不修改

#### Scenario: 删除二次确认

- **WHEN** 用户点击卡片「删除」
- **THEN** 弹出二次确认（提示「删除后不可恢复」）；确认后计划被物理删除并从列表移除；取消则不删除

### Requirement: 底部导航（FR-NAV-01）

The system SHALL 提供固定底部 3 个 Tab：我的计划、旅行助手、个人中心；默认进入「我的计划」，当前 Tab 高亮，切换后保留各页状态。

#### Scenario: 默认进入与高亮

- **WHEN** 应用启动
- **THEN** 进入「我的计划」Tab 且该 Tab 高亮

#### Scenario: 切换 Tab 保留状态

- **WHEN** 用户在「我的计划」页输入搜索关键字后切到「旅行助手」再切回
- **THEN** 「我的计划」页保留此前的搜索条件与列表状态
